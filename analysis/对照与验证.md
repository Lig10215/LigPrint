# DLabel 对照与 LigPrint 验证

## 静态对照

REA CLI 的 `inspect-pe-resources` 已读取原包 DLabel.exe，结果保存在 `pe-resources.json`。该文件为 Qt 原生 x86 PE32，SHA-256 为 `149ecf769724c5e181d8137d7e067c4483375fc25e4f18aae347a6668803fb1e`。PE 资源证据提供文件身份、架构和图标资源信息。以下功能推断另取自原包配置、Qt 元对象字符串、Qt 资源表和机器指令。

| 原包观察 | LigPrint 对应实现 |
|---|---|
| Module.dxml 分别注册数据库解析、本地数据库、打印服务、指令打印、图片打印及网络模块 | 独立实现本地工作簿读取、对象渲染、驱动打印及 PDF 输出 |
| DLibXls.dll 通过序号导入 libxls。反汇编可定位 xls_open、xls_getWorkSheet、xls_parseWorkSheet、xls_close_WS、xls_close_WB 的调用 | 识别本机 Excel 文件，枚举工作表，预览后将字段绑定到标签对象 |
| 主程序含 chooseLocalExcelFile、loadExcelFile、updatePreviewExcelData、confirmLoadExcelFile 及 batchprintSelected | 工作表选择与预览、字段选择、记录范围、逐条多份输出 |
| GraphicsScene、ItemPropertyBrowser、openLabelSlot 和 addVariablePrintPage 可定位到主程序 | 毫米画布、对象属性、模板读取和可变打印 |
| Qt 资源树的 shortcutToolbar 下有 align、rotate、layer、mirror、lock 等按钮资源 | 对齐、旋转、图层次序、镜像及位置锁定 |
| 原包包含云服务、网页引擎、推送和升级组件 | LigPrint 使用 WinForms、本地文件和 Windows 本地打印接口 |

`inspect_reference.py` 及 `native-evidence.txt` 给出 DLL 调用位置和程序字符串偏移。`list_resources.py` 按目标文件的 Qt 资源注册调用位置枚举资源名。对照结论来自静态分析，没有启动 DLabel 或进行逐屏比对。专有模板序列化协议、云接口及厂商打印指令没有移植。LigPrint 使用独立代码和本地依赖，发行物未包含 DLabel 二进制。

## 验证范围

- 本机为 Windows 11 专业版 x64。通过 PE 文件头核对便携程序与安装器均为 AMD64。
- 使用独立目录完成安装、启动和卸载。安装得到的应用与便携程序 SHA-256 相同。
- 通过桌面控件执行新建、插入对象、导入 Excel、字段绑定、切换记录、预览与返回、刷新、保存、重开及批量 PDF 输出。
- 多工作表 XLSX 能区分工作表，六位编号显示为 000012、000013。另用 BIFF XLS 验证 42 按格式显示为 00042。
- 重开模板后字段仍能逐行取值。四页 PDF 的纸张实测约为 60.000 × 40.000 mm。使用独立条码识别库回读每一页的 QR 和 Code 128，两种编码均按 000012、000012、000013、000013 排列。
- 验证本地路径校验拒绝 URL 和 UNC 输入。查看源码确认数据导入只读取本地文件流，PDF 直接在本地生成，1.0 版实体队列按本地端口类型筛选；该限制已在 1.1 版移除。第三方打印驱动、Windows 服务和系统外部进程的联网行为不在此次应用验证范围内。
- 单独解码程序能使用维护私钥读取事件。两个发行物仅包含应用所需的公钥。
- 实体标签机走纸、热敏输出质量、特定驱动适配与其他 Windows 版本的实机兼容性尚未验证。


## 1.1 版反馈修复

旧版从 HKLM 本地队列子键读取名称，排除共享名称，再用 Ports.Physical 的监视器类型和设备端口匹配，遗漏了共享队列、厂商端口及虚拟队列。1.1 改为对本机调用 EnumPrintersW 的 LOCAL 与 CONNECTIONS、级别 4，使用队列原名提交打印。枚举失败时提示系统错误，并保留内置 PDF 导出。

验证机返回 Fax、Microsoft Print to PDF、Microsoft XPS Document Writer、导出为WPS PDF。与 Win32_Printer 清单一致，对话框另有内置 PDF 导出。首次默认项是系统默认的 Microsoft Print to PDF。通过该 Windows 驱动实际提交两条 Excel 记录，输出两页，分别读到 000012 和 000013。验证机没有用户截图中的 Brother 和 2120TU 队列，未做这两台设备或共享打印机的实机走纸测试。

DLabel.exe 文件偏移 0x00e5c9cd 有 action_saveaspng_triggered 动作。工作区没有提供真实 .ddl 样本，本版采用 DLabel 导出 PNG、LigPrint 按毫米导入的方式转换固定版式。使用本地 PNG 样图完成了界面转换、保存、重开，并验证了图片字节、标签尺寸、Excel 叠印及两页输出。未验证用户实际模板在 DLabel 中的导出效果。

复验可在 Windows PowerShell x64 执行 LigPrint/tools/Verify.ps1。驱动测试仅向已存在的 Microsoft Print to PDF 队列提交作业，测试文件保存在本地临时目录。

## 1.2 版批量打印与对象编辑验证

对照反馈截图 03、04，1.2 版从“打印”入口打开三栏批量预览。Excel 列选择、原始记录编号和每行份数共同确定本次作业，右侧预览和两种输出路径使用同一套版式。Windows 队列枚举和上次使用的打印机沿用 1.1。

在 Windows PowerShell x64 运行 LigPrint/tools/Verify.ps1，可用 -Directory 指定本地结果目录。脚本会运行原有回归和 VerifyEditor.cs 的桌面控件测试。测试从模拟的 3407 条 Excel 导入后记录中通过搜索找到第 3、3407 条，检查列名搜索、全选和反选、单行勾选、筛选之外保留选择、Excel 份数字段、逐行份数及 90° 预览。随后向内置 PDF 和验证机的 Microsoft Print to PDF 驱动分别提交同一作业。

逐页栅格化两个实际输出文件并用独立二维码解码器读取，每份均为 5 页，内容按 0003、0003、3407、3407、3407 排列。固定字段取消参与输出后，模板对象数量和绑定保持原值。

画布测试覆盖 Ctrl 单击增选及取消、Ctrl+A、复制、连续粘贴、偏移、剪切、删除、多对象撤销与重做，并核对重做后的选区。将焦点转入实际属性文字编辑框后，对象快捷键没有复制或删除画布对象。测试未向实体打印机送纸。

## 1.2.1 版文件打开和勾选验证

1. 用同一有效模板启动旧版时，带路径仍得到“未命名标签”窗口。新版安装程序为当前用户注册 .lig 的 open 命令，程序和模板参数分别加引号。在含空格的安装目录中完成安装后，使用与资源管理器双击相同的 Windows Shell open 操作打开中文带空格的 .lig，确认启动的是安装版且标题显示该文件名。便携版用带空格的相对路径启动也通过。卸载后专用 ProgID 已清除。
2. 使用本地生成的 30 × 40 mm、1 个对象、8 条记录的模板，在窗口首次显示时检查画布对象、标题、记录数和首条绑定值。向已显示窗口的拖放事件传入标准 FileDrop 数据，检查第二份模板的文件名和两个对象均已加载。验证使用测试模板，未取得截图中的原文件。
3. 使用 8 条记录和顺序范围 1 至 2，向表格窗口发送鼠标按下、抬起消息。点第 4 行普通单元格仍为 2 条，点勾选格后变成第 1、2、4 条，右侧显示记录 4。第 4 行设为 3 份后，点击勾选格边缘取消，计数回到 2 条、2 张；再点框内勾回，得到 3 条、5 张。已核对提交的源记录索引、每条份数及实际导出 PDF 的 5 页。
4. 原有 3407 条记录筛选、批量份数、打印队列、对象复制及日志回归均通过。运行 tools/Verify.ps1 可复查窗口初始化、拖放数据和表格鼠标消息用例。

## 1.2.2 版表头全选验证

在 12 条记录的数据库列表上对第一列表头复选框发送鼠标按下和抬起消息，验证初始 12/12、两轮清空与恢复、手动取消一行后的半选状态，以及半选时点击表头恢复全选。检查复选框完整落在首列表头内。空选时右侧提示无选定记录，打印按钮禁用。

将其中一条的份数改为 3，再按关键字筛出 3 条。清除结果后剩 9 条；反选结果后恢复 12 条、14 张。过滤至零个匹配结果时，表头仍能清空和恢复整表。恢复全部记录后核对提交作业及 14 页的内置 PDF。复验入口为 tools/Verify.ps1。

## 1.3.0 版多行文字及打印裁切验证

在 Windows x64 上运行 `tools/Verify.ps1`。窗口测试双击固定文本框，在“编辑文字”中输入中文、回车及中英混排批号。鼠标拖动右下角后，测试检查文本框宽度减小、高度增加，再次缩窄到单字下限时宽度保持不变。将文本框拖出左纸边，保存并重新加载，检查换行内容及负坐标。

在 40 × 25 mm 标签上分别放置跨左边、完全在右边之外和完全在纸内的文本。逐像素比较设计和输出绘图，检查纸内图像相同，输出在纸外没有墨点。另将内置 PDF 和 Microsoft Print to PDF 驱动生成的两份文件栅格化，核对两处可见文字及实际墨点范围。该驱动回退到 A4 时，墨点仍位于左上角的标签尺寸内。本次未使用实体标签机走纸。
